# 什么是后端？

用户在网页上看到的是前端，但很多重要工作发生在服务器上：保存账号信息、查询文章、校验权限、计算订单金额，这些通常属于后端负责的范围。

可以把餐厅点餐类比成一次网络访问：

- 前端是菜单和点餐页面。
- API 是服务员与厨房之间约定好的传话方式。
- 后端是厨房和订单系统。
- 数据库是保存食材、菜单和订单记录的仓库。

前端不应该直接操作数据库，而是通过后端提供的 API 获取数据或提交操作。

## API 是什么？

API 是应用程序之间交流时使用的一组规则。它会约定：

- 请求应该发送到哪个地址。
- 使用什么 HTTP 方法。
- 参数应该放在哪里。
- 成功或失败时返回什么数据。

例如，一个获取文章列表的接口可能是：

```text
GET https://example.com/api/articles
```

服务器可能返回 JSON：

```json
{
  "items": [
    {
      "id": 1,
      "title": "什么是编程？"
    }
  ],
  "total": 1
}
```

JSON 是一种常见的数据交换格式，使用对象、数组、字符串、数字和布尔值表达信息。

## 常见的 HTTP 方法

- GET：读取资源，例如获取文章列表。
- POST：创建资源，例如提交一篇文章。
- PUT 或 PATCH：修改资源。
- DELETE：删除资源。

方法表达的是意图，权限校验仍然必须由后端完成。不能因为前端隐藏了一个按钮，就认为用户无法调用对应接口。

## 请求和响应

一次 API 调用至少包含请求和响应两部分。请求可能包含 URL、方法、请求头和请求体；响应通常包含状态码、响应头和响应体。

常见状态码包括：

- 200 OK：请求成功。
- 201 Created：资源创建成功。
- 400 Bad Request：请求参数不正确。
- 401 Unauthorized：需要登录或身份凭证无效。
- 403 Forbidden：身份存在，但没有权限。
- 404 Not Found：资源不存在。
- 500 Internal Server Error：服务器内部发生错误。

前端应根据状态码给用户清晰反馈，后端也应返回稳定、可理解的错误结构。

## 后端需要数据库吗？

很多后端应用会使用数据库保存长期数据，但不是所有服务都必须使用数据库。静态博客可以在构建时从 MDX 文件读取文章，不需要运行时数据库；而账号、订单、评论等需要持续写入的数据通常需要数据库。

CodeSeed 当前采用 Contentlayer + MDX：文章作为代码仓库中的文件管理，构建时生成页面。这种方式适合内容型展示项目，也便于版本控制。

## 如何开始学习后端？

可以按这个顺序实践：

1. 学习 HTTP、URL、状态码和 JSON。
2. 使用 Node.js、Python 或 Go 写一个返回 JSON 的小服务。
3. 为服务增加参数校验和错误处理。
4. 再学习数据库、身份认证和部署。

理解“请求进来、后端处理、响应出去”这条主线，比一开始记忆复杂框架 API 更重要。
