# HTTP 请求是怎样完成的？

当你在浏览器中打开一个网页，浏览器并不是直接“拿到”页面，而是要经过一系列网络步骤。理解这个流程，有助于排查接口超时、域名错误和证书问题。

下面以访问 https://example.com/ 为例。

## 1. 解析域名

浏览器首先需要知道 example.com 对应哪台服务器，这一步由 DNS 完成。DNS 可以理解为互联网的电话簿：把人类容易记忆的域名转换成 IP 地址。

浏览器和操作系统通常会先检查缓存。如果缓存中没有结果，才会向 DNS 服务器发起查询。

## 2. 建立连接

拿到 IP 地址后，客户端需要和服务器建立网络连接。基于 TCP 的连接通常包含握手过程，用来确认双方可以正常通信。

HTTPS 还需要 TLS 握手。TLS 会验证服务器证书，并协商加密通信使用的参数。证书异常、域名不匹配或证书过期，都会导致浏览器发出安全警告。

## 3. 发送 HTTP 请求

连接建立后，浏览器发送 HTTP 请求。一个简化的请求如下：

```http
GET / HTTP/1.1
Host: example.com
Accept: text/html
```

请求行包含方法、路径和协议版本；Host 告诉服务器访问的是哪个域名。实际请求还会包含 User-Agent、Cookie、缓存控制等请求头。

## 4. 服务器处理并返回响应

服务器收到请求后，可能会读取文件、查询数据库、调用其他服务，最后返回响应：

```http
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8

<html>...</html>
```

响应状态码表示处理结果，响应头描述数据类型和缓存策略，响应体承载真正的内容。

## 5. 浏览器渲染页面

浏览器拿到 HTML 后，会继续请求 HTML 中引用的 CSS、JavaScript、图片和字体。然后解析 HTML 创建 DOM，解析 CSS 创建样式规则，执行 JavaScript，最终把页面绘制到屏幕上。

这也是为什么一个页面可能需要多个网络请求。打开浏览器开发者工具的 Network 面板，可以查看每个请求的地址、状态码、耗时和响应内容。

## 常见问题如何定位？

- **域名无法访问**：先检查 DNS 解析是否正确。
- **连接超时**：检查服务器是否运行、端口是否开放和网络是否可达。
- **HTTPS 警告**：检查证书域名、有效期和证书链。
- **404**：服务器已收到请求，但对应资源不存在。
- **500**：服务器代码或依赖服务出现异常。
- **响应很慢**：比较 DNS、连接、服务器处理和下载各阶段耗时。

HTTP 是前后端协作的共同语言。掌握请求从域名到响应的过程后，再学习 REST API、缓存、Cookie 和 CDN，会更容易建立完整的 Web 知识体系。
