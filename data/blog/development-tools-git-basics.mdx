# Git 常用命令入门

Git 是一个分布式版本控制系统。它可以记录文件的变化，让你知道代码改了什么、什么时候改的，也能在需要时回到以前的版本。

## 创建或获取仓库

进入项目目录后，可以初始化一个新仓库：

```bash
git init
```

如果项目已经托管在远程平台，可以克隆它：

```bash
git clone https://example.com/demo.git
cd demo
```

git init 会创建本地仓库；git clone 会下载远程仓库及其历史记录。

## 查看和保存变化

最常用的检查命令是：

```bash
git status
```

修改文件后，先把希望提交的文件放入暂存区：

```bash
git add app/page.tsx
```

也可以暂存当前目录下的所有修改，但使用前要确认没有把密钥、日志或临时文件加入：

```bash
git add .
```

然后创建一次提交：

```bash
git commit -m "更新首页文案"
```

一次提交应该表达一个清晰的变化，例如“增加文章搜索”或“修复移动端导航”，不要把很多互不相关的工作混在一起。

## 查看历史

查看最近的提交：

```bash
git log --oneline
```

查看当前文件和最近一次提交的差异：

```bash
git diff
```

提交前通过 git diff 检查内容，可以减少误提交和拼写错误。

## 使用分支

分支让你可以在不影响主分支的情况下开发新功能：

```bash
git switch -c feature/article-search
```

功能完成并提交后，可以切回主分支：

```bash
git switch main
```

再根据团队流程合并分支：

```bash
git merge feature/article-search
```

多人协作时，合并前要先同步远程变化，并认真处理冲突。冲突文件中的标记需要人工修改，不能直接把冲突标记提交进去。

## 与远程仓库同步

常见命令包括：

- git remote -v：查看远程仓库地址。
- git pull：获取远程提交并合并到当前分支。
- git push：把本地提交推送到远程仓库。

不要把 .env、密码、访问令牌和生产环境密钥提交到 Git。即使之后删除文件，密钥也可能已经存在于提交历史中。

## 一个安全的日常流程

1. git status 查看当前状态。
2. 编写代码并运行测试。
3. git diff 检查具体变化。
4. git add 只暂存相关文件。
5. git commit -m "..." 保存一个清晰的提交。
6. 需要协作时再 git pull 和 git push。

Git 的价值不只是“上传代码”，更重要的是让每次变化可追踪、可解释、可恢复。养成小步提交的习惯，后续学习框架和参与团队项目都会轻松很多。
